# openv2b end-to-end verification plan

Goal: demonstrate that the simulator is *feature-complete for its v0.2 scope* and *numerically
accurate*: every physical, behavioral, and billing property either has a passing test or a
documented gap. Method: (A) feature audit, (B) invariant + property tests, (C) a month-long dummy
dataset where every reported metric is cross-checked against an independent theoretical
calculation, (D) independent review of this plan and of the executed result by separate
high-capability reviewer agents.

Persistence semantics to implement (F11): sessions of the same `vehicle_id` are chained in
arrival order; a later session's arrival SoC = clamp(previous departure SoC - depletion_kwh,
min_soc, capacity), where `depletion_kwh` is a new per-session input column. The first session
uses `soc_arrival_kwh` as today. Sessions of one vehicle must not overlap. A `persistence`
manifest flag (default on when depletion column present) allows disabling for A/B tests.

## B. Physical & behavioral properties (each = at least one test)

P1 energy conservation per session (with asymmetric efficiencies)
P2 SoC within [floor, capacity] always
P3 no export: net >= 0 every slot, adversarial discharge scenario
P4 per-direction power caps: per-session and aggregate
P5 V2B never sacrifices a departure target (discharge budget)
P6 charger exclusivity: one session per charger per slot; queue fairness (FIFO by arrival, id)
P7 unserved sessions reported, never dropped
P8 determinism (byte-identical serialization, twice)
P9 DR window (start,end] boundary inclusion/exclusion
P10 bill identity: total = energy + demand + penalty - incentive
P11 overflow definition: windowed positive part x slot-hours
P12 incentive paid only on honored windows
P13 feasible targets met by every policy
P14 uncontrolled = upper envelope: no policy delivers more energy per session than uncontrolled by departure when uncontrolled meets target
P15 persistence chaining: arrival SoC of session k+1 = clamp(departure SoC of k - depletion)
P16 persistence + banking: surplus charged in session k reduces grid energy needed in k+1 by exactly the surviving surplus (lossless case)
P17 persistence off (flag) reproduces independent-session behavior
P18 empty edge cases: zero vehicles, zero chargers, DR window fully outside horizon, vehicle with target below arrival SoC
P19 property-based sweep: N randomized scenarios (seeded), all of P1-P12 asserted on each
P20 policy-layer unit tests: EDF ordering, LLF laxity ordering + tie-breaks, taper-free headroom allocation exactness

## C. Month-long dummy dataset + theoretical cross-checks

Dataset `examples/one_month/` (generated by a seeded Rust binary `gen_month`, committed as CSVs):
- 30 days x 96 slots = 2880 slots, slot = 15 min.
- 8 vehicles with distinct roles: commuter (daily 9-17h), overnight resident (18-8h), surplus
  V2B donor (arrives high SoC), deficit heavy user, occasional visitor (3 sessions/month),
  never-connectable (overlaps when all chargers busy), min-SoC-constrained, unidirectional-only.
- Persistence: commuter/resident recur daily with fixed depletion; visitor recurs weekly.
- 4 chargers (2 bidirectional).
- Building load: deterministic daily double-hump profile (closed form, so theory can integrate it).
- Prices: 3-level TOU (super-off-peak 0-6h, off-peak 6-16h & 21-24h, peak 16-21h).
- DR: 8 events (2/week, weekdays, 17-19h) with FSL below the evening hump, baseline above it.
- Demand charge on peak-TOU class only (after F9).

Every value is chosen so closed-form hand calculation is possible (flat segments, integer-slot
boundaries, power levels that divide evenly).

Independent referee: a *separate* checker (Python, stdlib only, `tools/referee.py`) that reads the
same scenario CSVs and the simulator's `slots.csv`/`sessions.csv` outputs and recomputes every
metric below from first principles, using an independent implementation (different author-path
from the Rust engine; simple loops, no shared code). For the uncontrolled policy it additionally
recomputes the full expected slot-by-slot trajectory analytically and compares against `slots.csv`
exactly. For heuristic policies it verifies all invariants and re-derives the bill from the slot
series.

### Metrics checked (referee recomputes each; mismatch > 1e-6 fails)

Per session (sessions.csv):
M1 energy drawn (kWh), M2 energy exported (kWh), M3 departure SoC, M4 target met flag,
M5 missing charge = max(0, target - departure SoC), M6 excess charge / banked = max(0, departure - target),
M7 never_connected flag, M8 arrival SoC of chained sessions (persistence identity).

Per slot (slots.csv):
M9 building kW echoes input, M10 EV charge kW, M11 EV discharge kW, M12 net = building + charge - discharge,
M13 price echoes input, M14 net >= 0.

Aggregate / month (summary.json):
M15 total EV energy delivered, M16 total EV energy discharged, M17 building energy (kWh),
M18 imported energy (kWh), M19 energy cost ($) = sum(import x price),
M20 peak demand (kW) overall and per TOU class, M21 demand charge ($),
M22 per-DR-event overflow (kWh), M23 DR penalty ($), M24 DR incentive ($),
M25 total bill identity, M26 sessions served / unserved counts, M27 targets met count,
M28 total missing charge (kWh), M29 total banked charge (kWh),
M30 DR-window load relaxation: mean net kW inside DR windows, V2B policy vs charge-only twin vs
uncontrolled (the "building load relaxation" measure), M31 peak reduction vs uncontrolled.

Analytical closed-form checks (uncontrolled policy, computed by hand in the test comments):
- exact slot-by-slot charge profile for each vehicle archetype,
- exact monthly energy cost and demand charge,
- exact persistence chain SoC values for the commuter across all 30 days.

### Execution matrix

Run all 5 policies (uncontrolled, edf, llf, edf-v2b, llf-v2b) x {persistence on} on
one_month, plus uncontrolled x {persistence off} for P17. Referee validates every run.
Results tabulated in the overnight report (bill decomposition per policy, M30/M31 table).

## D. Review loops (independent reviewer agents)

R1 Plan review (before execution): a reviewer agent checks this plan for missing features,
missing metrics, missing failure modes, and wrong physics/tariff assumptions. Findings folded in.
R2 Post-execution audit: reviewer agents check (a) engine + billing code against SPEC.md for
correctness, (b) the test suite against sections B/C for coverage gaps (does every property have
a test that would actually fail under mutation?), (c) referee independence and correctness.
R3 Any confirmed finding becomes a fix + a regression test, and the report records it.

## Exit criteria

- All feature-matrix rows "done" or explicitly documented as out-of-scope gaps.
- All B-properties and C-metrics green under the referee.
- R2 findings fixed or documented.
- Only then: solver layer + MPC (separate plan section in the report).
